# Иерархия `Throwable`: корень всех проблем
`java.lang.Throwable` — это базовый класс для всего, что может быть «выброшено» (`throw`) и «поймано» (`catch`) в Java. 
Вы не можете использовать его напрямую, но все исключения и ошибки являются его наследниками.
```bash
Throwable
├── Exception
│   └── RuntimeException (и его наследники — непроверяемые)
│   └── ... (другие наследники — проверяемые)
└── Error
    └── ... (например, OutOfMemoryError, StackOverflowError)
```
Ключевое разделение происходит на два прямых подкласса: `Exception` и `Error`.

# `Error`: фатальные сбои JVM
`Error` — это базовый класс для серьёзных проблем на уровне виртуальной машины Java (JVM). 
Это критические сбои, из которых программа обычно не может и не должна восстанавливаться.

- `OutOfMemoryError` — закончилась память.
- `StackOverflowError` — переполнение стека (например, из-за бесконечной рекурсии).
- `NoClassDefFoundError` — не найден нужный класс.

# `Exception`: «рабочие» ошибки программы
`Exception` — это базовый класс для обычных ошибок, которые могут возникнуть в программе и которые можно и нужно обрабатывать. 
Именно с наследниками `Exception` работает большинство ваших блоков `try-catch`.

Внутри `Exception` выделяют две большие группы: проверяемые (checked) и непроверяемые (unchecked).

## Проверяемые (Checked) исключения
Это исключения, которые компилятор заставляет вас обработать. 
Если метод может выбросить такое исключение, вы обязаны либо обернуть вызов в `try-catch`, либо указать его в сигнатуре метода через `throws`.
Когда возникают: Обычно связаны с внешними ресурсами (файлы, сеть, базы данных), где сбой — это нормальная часть работы, и программист может на него отреагировать.
```java
// Компилятор требует обработать или пробросить IOException
public void readFile(String path) throws IOException {
    FileReader reader = new FileReader(path); // может выбросить IOException
}
```

## Непроверяемые (Unchecked) исключения
Это исключения, которые не требуют обязательной обработки компилятором. 
Они наследуются от `RuntimeException` (или от `Error`, но `Error` мы не обрабатываем).
Когда возникают: Как правило, это ошибки в логике программы (баги), которые следует не обрабатывать, а исправлять в коде.
```java
// Компилятор не заставляет обрабатывать NullPointerException
public int getLength(String s) {
    return s.length(); // если s == null, будет выброшено NullPointerException
}
```

Рекомендация Oracle: Если клиентский код может разумно восстановиться после исключения — делайте его проверяемым. 
Если нет (это программная ошибка) — непроверяемым.

# Обработка исключений: `try`, `catch`, `finally`
Для обработки используются три ключевых блока:
- `try`: Содержит код, который может выбросить исключение.
- `catch`: Перехватывает и обрабатывает конкретный тип исключения. Всегда перехватывайте как можно более конкретный тип, а не общий `Exception` или `Throwable`.
- `finally`: Блок, который выполняется всегда (и при нормальном завершении, и при исключении). Используется для освобождения ресурсов. Блок `try` может существовать без `catch`, но с `finally`.

Современная альтернатива (Java 7+): `try-with-resources` — автоматически закрывает ресурсы, реализующие `AutoCloseable`, избавляя от необходимости писать `finally` вручную.
