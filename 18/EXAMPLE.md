# `Object`: корень иерархии классов
`java.lang.Object` — это класс, который находится на вершине иерархии классов в Java. 
Каждый класс, будь то ваш собственный, стандартный класс из библиотеки или даже массив, является его потомком. 
Именно поэтому все объекты в Java обладают набором общих методов, унаследованных от `Object`.

Вы можете не использовать эти методы напрямую, но для многих из них предусмотрено переопределение, чтобы поведение объекта соответствовало его логике, а не стандартной реализации.

# `equals()`: логическое равенство
Назначение: определить, «равен» ли текущий объект другому объекту.
Реализация по умолчанию в `Object` сравнивает ссылки, то есть возвращает `true`, только если обе переменные указывают на один и тот же объект в памяти (эквивалентно оператору `==`). 
Это самое строгое из возможных определений равенства.
Переопределяя `equals()`, вы задаёте логическое равенство на основе состояния объекта (например, два разных объекта `Person` с одинаковым `id` могут считаться равными).

## Контракт `equals()`
Метод equals() должен удовлетворять следующим свойствам (это часть так называемого «контракта Object»). Нарушение этих правил — частая причина трудноуловимых ошибок.

- Рефлексивность: `x.equals(x)` всегда возвращает `true`. Объект всегда равен самому себе.
- Симметричность: `x.equals(y)` возвращает `true`, если и только если `y.equals(x)` возвращает `true`. Равенство не должно зависеть от порядка сравнения.
- Транзитивность: если `x.equals(y)` и `y.equals(z)`, то `x.equals(z)` также возвращает `true`. Если A равно B, а B равно C, то A равно C.
- Сравнение с `null`: `x.equals(null)` всегда возвращает `false`. Ни один не-null объект не равен null.
- Согласованность: Повторные вызовы `x.equals(y)` возвращают один и тот же результат, если объекты не изменялись. Результат не должен «мигать» между вызовами.
```java
public class Point {
    private final int x;
    private final int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    @Override
    public boolean equals(Object o) {
        // 1. Проверка на идентичность ссылок (быстрый путь)
        if (this == o) return true;
        // 2. Проверка на null и точное совпадение класса
        if (o == null || getClass() != o.getClass()) return false;
        // 3. Приведение типа и сравнение значимых полей
        Point point = (Point) o;
        return x == point.x && y == point.y;
    }
}
```

# `hashCode()`: хеш-код объекта
Назначение: вернуть целое число (хеш-код), которое используется в хеш-таблицах (например, `HashMap`, `HashSet`) для быстрого поиска и группировки объектов.
Реализация по умолчанию в `Object` часто (но не обязательно) основана на внутреннем адресе объекта в памяти, то есть у разных объектов, как правило, разные хеш-коды.

## Контракт `hashCode()`
- Согласованность: при повторных вызовах на одном и том же объекте `hashCode()` должен возвращать одно и то же число, если информация, используемая в `equals()`, не изменилась.
- Связь с `equals()`: Если два объекта равны согласно `equals()`, то их `hashCode()` ОБЯЗАНЫ быть одинаковыми.
- Обратное неверно: если объекты не равны, их хеш-коды могут быть одинаковыми (это называется коллизией), но для производительности лучше, чтобы они различались.

Золотое правило: Всегда переопределяйте `hashCode()`, если переопределяете `equals()`. Несоблюдение этого правила ломает работу `HashMap` и `HashSet`: вы можете положить объект в коллекцию, но не сможете его найти.

```java
import java.util.Objects;

@Override
public int hashCode() {
    return Objects.hash(x, y); // используем те же поля, что и в equals()
}
```

# `toString()`: строковое представление
Назначение: вернуть строковое представление объекта, которое используется для отладки, логирования и вывода информации.
Реализация по умолчанию возвращает строку в формате `ИмяКласса@шестнадцатеричный_hashCode`, например `Point@1b6d3586`. Эта информация почти бесполезна для человека.
Best practice: Всегда переопределяйте `toString()` в своих классах. Хорошая реализация должна содержать ключевые поля объекта, чтобы по строке можно было понять его состояние.
```java
@Override
public String toString() {
    return "Point{x=" + x + ", y=" + y + '}';
}
```

# `getClass()`: информация о типе во время выполнения
Назначение: вернуть объект `Class<?>`, который представляет фактический (runtime) тип объекта, то есть класс, экземпляром которого он является.
Ключевая особенность: этот метод объявлен как `final`, поэтому его нельзя переопределить. 
Он всегда возвращает точный класс объекта, независимо от типа ссылки, через которую он вызывается.
```java
Object obj = new Point(1, 2);
Class<?> clazz = obj.getClass(); // вернёт class Point
```
Метод широко используется в рефлексии и для получения метаданных о классе. 
Например, `getClass().getName()` вернёт полное имя класса, а `getClass().getSimpleName()` — короткое имя.
