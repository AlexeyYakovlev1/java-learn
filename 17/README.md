# Что такое абстракция?
Абстракция — это принцип, при котором мы выделяем общие, существенные характеристики объектов и отбрасываем детали, не важные для текущей задачи. 
В Java абстракция достигается через:
- Абстрактные классы (`abstract class`) — для близкородственных классов, разделяющих общее состояние и поведение.
- Интерфейсы (`interface`) — для описания контракта, которому могут следовать любые, даже несвязанные классы.

Ключевая идея: и абстрактные классы, и интерфейсы нельзя инстанцировать напрямую. Они созданы для того, чтобы их наследовали или реализовывали.

## Абстрактные классы (`abstract class`)
Абстрактный класс — это класс, помеченный ключевым словом `abstract`. Он может содержать как абстрактные методы (без реализации), так и конкретные методы (с реализацией).
Абстрактный метод — это метод, объявленный без тела (без фигурных скобок), просто с точкой с запятой:
```java
abstract void moveTo(double deltaX, double deltaY);
```
Если класс содержит хотя бы один абстрактный метод, он обязан быть объявлен абстрактным.
```java
public abstract class GraphicObject {
    // Поля — могут быть любого типа, не только static final
    protected int x, y;
    protected String color;

    // Конкретный метод с реализацией
    public void moveTo(int newX, int newY) {
        this.x = newX;
        this.y = newY;
    }

    // Абстрактный метод — без реализации
    // Наследники ОБЯЗАНЫ его реализовать
    public abstract void draw();

    // Ещё один конкретный метод
    public void setColor(String color) {
        this.color = color;
    }
}
```

Наследники абстрактного класса обычно реализуют все его абстрактные методы. Если какой-то метод не реализован, наследник тоже должен быть объявлен `abstract`.
```java
public class Circle extends GraphicObject {
    private double radius;

    @Override
    public void draw() {
        System.out.println("Рисую круг радиусом " + radius);
    }
}

public class Rectangle extends GraphicObject {
    private double width, height;

    @Override
    public void draw() {
        System.out.println("Рисую прямоугольник " + width + "x" + height);
    }
}
```

### Когда использовать абстрактный класс
- Вы хотите разделить код между несколькими близкородственными классами.
- Вы ожидаете, что наследники будут иметь много общих методов или полей.
- Вы хотите объявить нестатические или нефинальные поля (то есть общее состояние).
- Вам нужны модификаторы доступа, отличные от `public` (например, `protected` или `private`) для методов.

# Интерфейсы (`interface`)
Интерфейс — это ссылочный тип, который определяет контракт (набор методов), которому должны следовать реализующие его классы. До Java 8 интерфейс мог содержать только абстрактные методы и константы. Сейчас возможности расширены.
- Все поля автоматически являются `public static final` (константы).
- Все методы, не объявленные как `default` или `static`, автоматически являются `public abstract` (ключевое слово `abstract` можно опустить).
- Класс может реализовать любое количество интерфейсов.
- Интерфейс не может содержать instance-полей и конструкторов (то есть не может хранить состояние).
```java
public interface Drawable {
    // Константа (public static final неявно)
    int MAX_SIZE = 100;

    // Абстрактный метод (public abstract неявно)
    void draw();

    // Ещё один абстрактный метод
    String getDescription();
}
```
```java
public class Circle implements Drawable {
    private double radius;

    @Override
    public void draw() {
        System.out.println("Рисую круг");
    }

    @Override
    public String getDescription() {
        return "Круг радиусом " + radius;
    }
}
```

## Когда использовать интерфейс
- Вы ожидаете, что интерфейс будут реализовывать несвязанные классы (например, `Comparable`, `Cloneable`).
- Вы хотите указать поведение типа, но не заботитесь о том, кто его реализует.
- Вы хотите воспользоваться множественным наследованием типа (класс может реализовать несколько интерфейсов).

# Default-методы (Java 8+)
Default-метод — это метод в интерфейсе, который имеет реализацию по умолчанию. Он объявляется с ключевым словом `default`.
Зачем это нужно: до Java 8, если вы добавляли новый метод в интерфейс, все существующие классы, реализующие этот интерфейс, 
ломались — их нужно было перекомпилировать и добавить реализацию. Default-методы решают эту проблему, обеспечивая обратную совместимость.
```java
public interface TimeClient {
    void setTime(int hour, int minute, int second);
    LocalDateTime getLocalDateTime();

    // Default-метод с реализацией
    default String getFormattedDateTime() {
        LocalDateTime dt = getLocalDateTime();
        return dt.format(DateTimeFormatter.ISO_LOCAL_DATE_TIME);
    }
}
```

## Правила и особенности default-методов
- Не могут обращаться к instance-полям, так как интерфейсы не могут их содержать. Default-методы работают только поверх других методов интерфейса.
- Не могут переопределять `equals()`, `hashCode()` и `toString()` — эти методы принадлежат классу `Object` и недоступны для default-методов.
- Конфликты при множественном наследовании: если класс реализует два интерфейса с одинаковым default-методом, компилятор выдаст ошибку. Класс обязан переопределить этот метод:
```java
interface A {
    default void hello() { System.out.println("A"); }
}

interface B {
    default void hello() { System.out.println("B"); }
}

class C implements A, B {
    @Override
    public void hello() {
        A.super.hello(); // явный вызов default-метода из A
    }
}
```
- Приоритет классов над интерфейсами: если класс наследует конкретный метод от суперкласса и реализует интерфейс с таким же default-методом, метод класса побеждает — default-метод игнорируется.

Важно: интерфейс — это контракт («что делать»), абстрактный класс — это частичная реализация («что делать» + «как делать часть этого»).
