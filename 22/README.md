# Классический `try-catch-finally`
Эта конструкция позволяет перехватить исключение и гарантированно выполнить код очистки.

- `try`: Блок кода, в котором может возникнуть исключение.
- `catch`: Блок, который перехватывает и обрабатывает конкретный тип исключения. Можно указать несколько catch для разных типов.
- `finally`: Блок, который выполняется всегда, независимо от того, было ли выброшено исключение или нет. Он предназначен для освобождения ресурсов (закрытия файлов, соединений и т.д.). `try` может существовать без `catch`, но только с `finally`.

## Важная особенность: `return` внутри `finally`
Это коварный момент, о котором нужно знать. Если в блоке `finally` находится оператор `return`, он переопределит любое возвращаемое значение из блоков `try` или `catch`.
```java
public static int getValue() {
    try {
        return 1;
    } finally {
        return 2; // Это return переопределит return 1 из try
    }
}
// Вызов getValue() вернёт 2
```
Рекомендация: Избегайте использования `return` в блоке `finally`. Это делает поведение кода запутанным и является плохой практикой. Блок `finally` должен только освобождать ресурсы.

# Современный `try-with-resources` (Java 7+)
Этот механизм был создан для автоматического и безопасного закрытия ресурсов. Любой объект, реализующий интерфейс `AutoCloseable` (или его наследника `Closeable`), может быть использован в качестве ресурса.

Синтаксис: Ресурсы объявляются в круглых скобках сразу после `try`. После завершения блока `try` (нормального или аварийного) Java автоматически вызовет метод `close()` у каждого ресурса.
```java
try (BufferedReader br = new BufferedReader(new FileReader("file.txt"))) {
    // Работа с файлом
    return br.readLine();
} // Здесь br.close() будет вызван автоматически
```

### Преимущества перед классическим подходом
- Лаконичность: Код становится намного короче и чище, так как не нужно писать шаблонный `finally` с проверкой на `null`.
- Безопасность при исключениях (Suppressed Exceptions): Если исключение возникает и в теле `try`, и при вызове `close()`, классический `finally` «потеряет» исходное исключение из `try`, оставив только ошибку закрытия. `try-with-resources` же сохраняет исходное исключение, а исключение из `close()` добавляет к нему как подавленное (suppressed). Его можно получить через метод `getSuppressed()`.
- Гарантированное закрытие: Ресурс будет закрыт, даже если в блоке `try` произошло исключение.

## Порядок закрытия ресурсов
Если в одном `try-with-resources` объявлено несколько ресурсов, они закрываются в порядке, обратном порядку их объявления.
```java
try (ResourceFirst rf = new ResourceFirst();
     ResourceSecond rs = new ResourceSecond()) {
    // ...
} // Сначала будет закрыт rs, затем rf
```
