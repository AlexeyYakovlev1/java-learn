# Что такое `String`?
`String` — это класс в Java, который представляет неизменяемую (immutable) последовательность символов. Это означает, что после создания объекта `String` его содержимое нельзя изменить. Любая операция, которая, казалось бы, изменяет строку (например, конкатенация или `replace`), на самом деле создаёт новый объект `String`, а исходный остаётся неизменным.

Важное следствие: `String` — это не примитивный тип, а ссылочный тип (объект), но он имеет особый статус в языке: строковые литералы (значения в двойных кавычках) обрабатываются JVM особым образом

## Неизменяемость: как это устроено внутри
Внутри класса `String` символы хранятся в массиве:
- В JDK 8 и ранее — в `private final char[] value;`
- В JDK 9 и новее — в `private final byte[] value;` (для экономии памяти, так как большинство строк — Latin-1)

Ключевое слово `final` для массива означает, что ссылку на массив нельзя изменить, а `private` (в сочетании с отсутствием методов, возвращающих сам массив) — что содержимое массива недоступно для изменения извне. Любой метод, вроде `concat()`, `replace()` или `substring()`, создаёт и возвращает новый объект `String`.
```java
String str = "Hello";
str.concat(" World"); // создаётся новый объект, но мы его не сохраняем
System.out.println(str); // Выведет "Hello" — исходная строка не изменилась

String newStr = str.concat(" World"); // сохраняем результат
System.out.println(newStr); // Выведет "Hello World"
```

## Пул строк (`String Pool`)
Пул строк (или «интерн-пул») — это специальная область в куче (heap) памяти, где JVM хранит канонические (уникальные) экземпляры строковых литералов. Его существование возможно именно благодаря неизменяемости `String`: раз строку нельзя изменить, её можно безопасно переиспользовать.

Как это работает:
- Когда вы пишете строковый литерал `String s = "Java";`, JVM сначала ищет строку с таким же содержимым в пуле. Если находит — возвращает ссылку на существующий объект. Если нет — создаёт новый и помещает его в пул.
- Это позволяет экономить память: все литералы с одинаковым содержимым указывают на один и тот же объект в пуле.
```java
String s1 = "Java"; // создаётся в пуле
String s2 = "Java"; // находит в пуле и возвращает ту же ссылку

System.out.println(s1 == s2); // true — это один и тот же объект
```

## Два способа создания строки: литерал vs `new String()`
- `String s = "Java";`: Ищет в пуле; если нет — создаёт в пуле
- `String s = new String("Java");`: Всегда создаёт новый объект в куче вне пула

### Сколько объектов создаётся при `new String("Java")`?
- Если строки "Java" ещё нет в пуле — сначала создаётся объект в пуле, затем новый объект в куче. Итого — 2 объекта.
- Если "Java" уже есть в пуле — создаётся только новый объект в куче. Итого — 1 объект.

## Сравнение
```java
String s1 = "Java";
String s2 = "Java";
String s3 = new String("Java");

System.out.println(s1 == s2); // true  (один объект в пуле)
System.out.println(s1 == s3); // false (разные объекты: пул vs куча)
System.out.println(s1.equals(s3)); // true  (сравнение содержимого)
```

## Метод `intern()`
Метод `intern()` позволяет вручную поместить строку в пул (или получить из пула существующую).

- Если пул уже содержит строку с таким же содержимым — возвращается ссылка на объект из пула.
- Если нет — объект добавляется в пул, и возвращается ссылка на него.
```java
String s1 = new String("Java"); // объект в куче
String s2 = s1.intern();        // получаем строку из пула

System.out.println(s1 == s2); // false (s1 в куче, s2 в пуле)
System.out.println(s2 == "Java"); // true (s2 из пула)
```

## `StringBuilder` и `StringBuffer`: изменяемые строки
Когда нужно много раз изменять строку (особенно в цикле), использование `String` крайне неэффективно, так как каждый раз создаётся новый объект. Для этого предназначены классы `StringBuilder` и `StringBuffer`.
Оба класса наследуются от `AbstractStringBuilder` и хранят изменяемый массив символов (в отличие от `String`).

## Производительность: почему `StringBuilder` быстрее?
`StringBuilder` не выполняет синхронизацию, что делает его значительно быстрее `StringBuffer` в однопоточных сценариях. 
Синхронизация `StringBuffer` накладывает дополнительную нагрузку на производительность. В бенчмарках разница может достигать 30–40% и более.
```java
// ❌ Плохо: создаёт 1000 новых объектов String
String result = "";
for (int i = 0; i < 1000; i++) {
    result += i; // каждый раз создаётся новый String
}

// ✅ Хорошо: использует один изменяемый буфер
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) {
    sb.append(i); // изменяет внутренний массив
}
String result = sb.toString();
```

## Основные методы `StringBuilder` / `StringBuffer`
- `append(x)`: добавляет строку к текущему содержимому
- `insert(index, x)`: вставляет строку в указанную позицию
- `delete(start, end)`: удаляет часть строки
- `toString()`: возвращает итоговую строку
- `reverse()`: разворачивает строку
- `replace(start, end, x)`: заменяет часть строки

Внутренняя ёмкость: по умолчанию `StringBuilder` имеет ёмкость 16 символов. При переполнении она увеличивается по формуле: новая ёмкость = старая ёмкость * 2 + 2.
