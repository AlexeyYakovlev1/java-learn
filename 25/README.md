# Место `List` в иерархии коллекций
Java Collections Framework — это унифицированная архитектура для хранения и обработки групп объектов. Она состоит из двух основных деревьев интерфейсов: одно начинается с `Collection`, другое — с `Map`.

Интерфейс `Collection` предоставляет базовую функциональность (`add`, `remove` и т.д.), а его подинтерфейсы специализируют её:
- `Set` — не допускает дубликатов.
- `Queue` — предназначен для хранения элементов перед обработкой (обычно FIFO). 
- `List` — упорядоченная коллекция (последовательность). 

Именно `List` и его две основные реализации — `ArrayList` и `LinkedList` — являются предметом нашего разговора.

# Интерфейс `List`: что он гарантирует
`List` расширяет `Collection` и добавляет два ключевых свойства:
- Порядок: элементы хранятся в том порядке, в котором они были добавлены. Итерация по списку всегда будет возвращать их в этом же порядке.
- Индексация: каждый элемент имеет целочисленный индекс (начиная с 0), что позволяет точно контролировать позицию вставки и получать элементы по их позиции, как в массиве.

Кроме того, `List` разрешает дубликаты и (в большинстве реализаций) принимает `null`.

## Ключевые методы `List`
- `add(int index, E element)` -	Вставляет элемент на указанную позицию, сдвигая последующие элементы.
- `get(int index)` - Возвращает элемент по индексу.
- `set(int index, E element)` - Заменяет элемент по индексу, возвращая старый.
- `remove(int index)` - Удаляет элемент по индексу, сдвигая последующие.
- `indexOf(Object o) / lastIndexOf(Object o)` - Возвращают индекс первого/последнего вхождения элемента.
- `subList(int from, int to)` - Возвращает представление части списка.

Также `List` предоставляет специальный итератор `ListIterator`, который поддерживает двунаправленный обход и модификацию элементов.

# `ArrayList`: динамический массив
`ArrayList` — это реализация `List`, основанная на динамически расширяемом массиве.
- Элементы хранятся в непрерывном блоке памяти (массиве).
- Когда массив заполняется, создаётся новый массив большего размера (обычно в 1.5 раза), и все элементы копируются в него.
- Благодаря непрерывному хранению, доступ к элементу по индексу (`get`) выполняется за константное время O(1) — просто вычисляется адрес в памяти.

### Сильные стороны:
- Быстрый доступ по индексу — главное преимущество.
- Эффективное использование памяти — накладные расходы минимальны (только небольшой запас свободных ячеек в конце массива).
- Быстрая итерация — благодаря непрерывности данных и эффективному использованию кэша процессора, обход `ArrayList` обычно значительно быстрее, чем `LinkedList`.

### Слабые стороны:
- Медленная вставка/удаление в начало или середину — требует сдвига всех последующих элементов (сложность O(n)).

Настройка: `ArrayList` имеет один параметр настройки — начальную ёмкость (initial capacity), которая задаёт размер внутреннего массива до первого расширения.

# `LinkedList`: двусвязный список
`LinkedList` — это реализация `List`, основанная на двусвязном списке. Каждый элемент хранится в отдельном узле (`Node`), который содержит данные и ссылки на предыдущий и следующий узлы.
- Узлы разбросаны по памяти, а не хранятся непрерывно.
- Чтобы найти элемент по индексу, нужно пройти от начала (или конца) списка до нужного узла, поэтому `get(index)` выполняется за линейное время O(n). 

### Сильные стороны:
- Быстрая вставка/удаление в начало или конец — достаточно переставить ссылки, это занимает O(1). `LinkedList` хранит прямые ссылки на первый и последний элементы, что делает эти операции особенно быстрыми.
- Реализует интерфейс `Deque` (двусторонняя очередь), поэтому может использоваться как стек (LIFO) или очередь (FIFO) с эффективными операциями на обоих концах.

### Слабые стороны:
- Медленный доступ по индексу — O(n).
- Высокие накладные расходы по памяти — для каждого элемента создаётся объект `Node` с двумя ссылками (`prev` и `next`), что существенно увеличивает потребление памяти по сравнению с `ArrayList`.
- Медленная итерация — из-за "погони за указателями" (pointer chasing) и промахов кэша процессора обход `LinkedList` обычно медленнее.

# Как выбрать: практические рекомендации
Главное правило современной Java-разработки: по умолчанию выбирайте `ArrayList`.
`LinkedList` имеет смысл использовать только в специфических сценариях:
- Если вам очень часто нужно добавлять или удалять элементы в начале списка (операции `addFirst`, `removeFirst`).
- Если список используется как стек (LIFO) или очередь (FIFO) с частыми операциями на обоих концах. В этом случае `LinkedList` (или `ArrayDeque`) будет эффективнее.
- Если доступ по индексу не требуется или происходит очень редко.
