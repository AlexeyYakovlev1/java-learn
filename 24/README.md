# Зачем нужны дженерики?
Представьте класс `Box`, который может хранить объект любого типа. Без дженериков он использовал бы `Object`:
```java
public class Box {
    private Object object;
    public void set(Object object) { this.object = object; }
    public Object get() { return object; }
}
```
Проблема в том, что компилятор не может проверить, как используется класс. Одна часть кода может положить в Box число `Integer` и ожидать его на выходе, а другая — случайно передать `String`, что приведёт к ошибке во время выполнения (`ClassCastException`).

Дженерики решают эту проблему, позволяя параметризовать класс типом. Главные преимущества:
- Строгая проверка типов на этапе компиляции. Ошибки типа обнаруживаются сразу, а не во время выполнения.
- Устранение явных приведений типов. Код становится чище и безопаснее.
- Возможность создавать обобщённые алгоритмы, работающие с разными типами.

## Синтаксис и основные концепции
```java
public class Box<T> { // T — параметр типа
    private T t;

    public void set(T t) { this.t = t; }
    public T get() { return t; }
}
```

Соглашения об именовании параметров типа (одна заглавная буква):
- `E` — Element (элемент, часто в коллекциях)
- `K` — Key (ключ)
- `V` — Value (значение)
- `T` — Type (тип)
- `N` — Number (число)

### Обобщённые методы
Метод можно сделать дженериком, объявив параметр типа перед возвращаемым типом:
```java
public static <T> void printArray(T[] array) {
    for (T element : array) {
        System.out.print(element + " ");
    }
    System.out.println();
}
```

# Wildcards (подстановочные типы)
Важно помнить: дженерики в Java инвариантны. Это значит, что `List<String>` не является подтипом `List<Object>`, даже если `String` наследуется от `Object`.
Именно для смягчения этой жёсткости и нужны wildcards — подстановочные типы, обозначаемые символом `?`.

## Три вида wildcards
- `List<?>` - Список любого типа (неизвестного)
- `List<? extends Cat>` - Список типа `Cat` или его подтипов
- `List<? super Cat>` - `Cat` или любой его предок вплоть до `Object` (нижняя граница)

### Принцип PECS
Чтобы запомнить, какой wildcard использовать, существует мнемоника PECS (Producer Extends, Consumer Super) от Джошуа Блоха:
- Producer Extends: Если коллекция является поставщиком данных (вы только читаете из неё), используйте `? extends T`.
- Consumer Super: Если коллекция является потребителем данных (вы только пишете в неё), используйте `? super T`.
- Если коллекция используется и для чтения, и для записи — wildcard не подходит, нужен точный тип.

Важное правило: не используйте wildcards в качестве возвращаемого типа метода. Это делает API неудобным для клиента.

# Type Erasure (стирание типов)
Это механизм, благодаря которому дженерики в Java не создают новых классов во время выполнения и не несут накладных расходов в рантайме.
Как работает стирание типов:
- Компилятор заменяет все параметры типа на их границу (если она указана) или на `Object` (если граница не указана).
- При необходимости вставляет приведения типов (casts) для сохранения типобезопасности.
- Генерирует bridge-методы для сохранения полиморфизма в иерархиях наследования.

Пример: Дженерик-класс `Node<T>` после стирания превращается в обычный класс, где все `T` заменены на `Object`. В байт-коде не остаётся никакой информации о том, что это был дженерик.
