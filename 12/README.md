# Что такое модификаторы доступа?
Модификаторы доступа — это ключевые слова, которые регулируют уровень доступа к различным частям кода: классам, полям, методам и конструкторам. Они позволяют разработчику контролировать, кто может использовать тот или иной член класса, и являются основой для реализации принципа инкапсуляции.
В Java существует четыре уровня доступа, которые можно расположить от самого строгого к самому мягкому:

- `private` — только внутри класса.
- `default` (package-private, без ключевого слова) — только внутри пакета.
- `protected` — внутри пакета и в классах-наследниках.
- `public` — везде.

# Подробный разбор каждого модификатора
## `private` — самый строгий
Доступ к члену класса разрешён только внутри самого этого класса. Даже наследники не могут видеть `private`-члены
Когда использовать:
- Поля класса — почти всегда. Это основа инкапсуляции: скрываем внутреннее состояние и предоставляем доступ через геттеры и сеттеры.
- Вспомогательные методы, которые являются деталями реализации и не должны быть видны снаружи.
```java
public class Cat {
    private String secretName; // доступно только внутри класса Cat

    public void setSecretName(String name) {
        secretName = name; // внутренний метод может обращаться к private-полю
    }

    public String getSecretName() {
        return secretName;
    }
}
```

## `default` (package-private) — доступ внутри пакета
Если модификатор не указан явно, Java автоматически применяет доступ по умолчанию, который также называют package-private. Член класса виден всем классам внутри того же пакета, но не доступен за его пределами.
Когда использовать:
- Вспомогательные классы-утилиты внутри пакета, которые не должны быть видны извне
- Методы, предназначенные для внутреннего взаимодействия между классами одного пакета
```java
package services;

class Mapper { // package-private класс, виден только внутри пакета services
    // ...
}

public class UserService {
    Mapper mapper; // может использовать Mapper, так как они в одном пакете
}
```

## `protected` — доступ внутри пакета и в классах-наследниках
`protected` предоставляет доступ:
- Всем классам внутри того же пакета
- Классам-наследникам (подклассам) даже из других пакетов
Это промежуточный уровень между `default` и `public`, предназначенный для членов, которые должны быть доступны для расширения в подклассах, но не для всех.
Когда использовать:
- Методы и поля, которые нужны только наследникам для расширения
- Вспомогательные методы, полезные в дочерних классах
```java
package top_secret;

public abstract class AbstractSecretAgent {
    protected static int agentCount = 0; // доступно наследникам и классам того же пакета
}

package missions;

public class FBISecretAgent extends AbstractSecretAgent {
    public void report() {
        agentCount++; // наследник из другого пакета может обращаться к protected-полю
    }
}
```

## `public` - доступ везде
Самый мягкий модификатор. Член класса доступен из любого другого класса в любом пакете. 
Это наименее ограничивающий уровень доступа.
Когда использовать:
- Методы, которые являются частью публичного API класса — то, что должны видеть и использовать другие разработчики.
- Константы (`public static final`), которые представляют общие значения.
```java
public class MathUtils {
    public static final double PI = 3.14159; // публичная константа

    public static int add(int a, int b) { // публичный метод — часть API
        return a + b;
    }
}
```

# Best practices: как выбирать модификатор
- Принцип минимальной видимости (Principle of Least Privilege): всегда выбирайте самый строгий модификатор, который ещё позволяет решить задачу.Чем меньше кода видит ваш член класса, тем меньше риск случайного или злонамеренного изменения.
- Поля — почти всегда `private`. Исключение — настоящие константы (`public static final`).
- Методы делайте `public` только если они часть внешнего интерфейса класса. Вспомогательные методы — `private`.
- `protected` — для методов, которые нужны наследникам для расширения функциональности.
- `package-private` — для внутренних сервисных методов пакета, которые не должны быть видны снаружи.
- Порядок модификаторов: JLS рекомендует канонический порядок: аннотация → модификатор доступа → `static` → `final` и т.д. Например: `@Id private static final long ID = 1;`
